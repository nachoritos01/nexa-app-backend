# DEPLOYMENT.md — SaaS Template Mobile

> Complete guide to publish the app on App Store and Play Store.

---

## 1. Process Overview

```
Local development
      │
      ▼
Build with EAS (in the cloud)
      │
      ├──── Android AAB ────► Google Play Console ────► Play Store
      │
      └──── iOS IPA ─────────► App Store Connect ────► App Store
```

**EAS Build advantage:** You don't need a Mac for iOS builds, and you don't need to configure local signing. EAS manages certificates automatically.

## 2. Preparation (One-time setup)

### 2.1 Create developer account

**Apple Developer Program:**
- URL: developer.apple.com/programs
- Cost: $99 USD/year
- Requires: Personal Apple ID, tax information
- Approval: 24-48 hours

**Google Play Console:**
- URL: play.google.com/console
- Cost: $25 USD (one-time payment)
- Requires: Google account, tax information
- Approval: Immediate for account, new apps take 7-10 days

### 2.2 Configure EAS

```bash
# Login to Expo
eas login

# Initialize EAS in the project
eas init

# Configure credentials (EAS creates/manages them automatically)
eas credentials
```

### 2.3 Register the app

**In App Store Connect (iOS):**
1. Go to appstoreconnect.apple.com
2. `My Apps` → `+` → `New App`
3. Platforms: iOS
4. Name: `SaaS Template`
5. Bundle ID: `com.saas-template.mobile` (must match app.json)
6. SKU: `saas-template-mobile`
7. Save and copy the App ID (for `eas.json`)

**In Google Play Console (Android):**
1. Go to play.google.com/console
2. `Create app`
3. Name: `SaaS Template`
4. Type: App
5. Category: Business
6. Save and copy the Package Name (`com.saas-template.mobile`)

## 3. Android — Play Store

### 3.1 Configure signing (EAS manages it)

```bash
# EAS generates and manages the keystore automatically
# First time you build, EAS asks if it should create one

# If you prefer your own keystore (optional)
eas credentials --platform android
```

> **CRITICAL:** The keystore must be kept secure. If you lose it, you cannot publish updates for that app ever again. EAS stores it securely on its servers.

### 3.2 First AAB Build

```bash
# Production build (AAB — Android App Bundle)
eas build --profile production --platform android

# The build takes ~10-15 minutes
# When done: download URL for the .aab file
```

### 3.3 Upload to Play Store

**Option A: Manual (first time)**
1. Play Console → Your app → `Production` → `Create new release`
2. Upload the `.aab` generated by EAS
3. Release notes:
   ```
   v1.0.0 — Initial release
   • Order management
   • Instant price calculator
   • Customer portal
   • Sales dashboard
   ```
4. Review → Publish

**Option B: Automatic with EAS Submit**
```bash
# Requires: Google Play Service Account JSON

# Create Service Account in Google Cloud Console:
# 1. cloud.google.com → IAM → Service Accounts
# 2. Create account → Name: "EAS Submit"
# 3. Role: Play Store Admin
# 4. Create and download JSON key
# 5. In Play Console: Configuration → Service Accounts → Link

# Automatic submit
eas submit --profile production --platform android --latest
```

### 3.4 Configure the Play Store listing

Before publishing, complete in Play Console → Store listing:

| Field | Content |
|-------|-----------|
| Short name | SaaS Template |
| Full name | SaaS Template — Business Management |
| Short description | Manage orders, quotes and production from your phone |
| Full description | (see below) |
| Screenshots | Minimum 2 captures of each main section |
| Icon | 512x512 PNG |
| Feature graphic | 1024x500 JPG/PNG |
| Category | Business |
| Support email | support@your-domain.com |
| Privacy policy | URL to your policy |

**Full description (Play Store):**
```
SaaS Template is a specialized CRM for service businesses and production shops.

Manage your entire business from your phone:

PRODUCTION ORDERS
• Create and track orders step by step
• Follow status in real time: received, confirmed, in production, ready, delivered

• Savings suggestions for your customers

DASHBOARD
• Daily stats: revenue, orders, deposits

• Weekly activity charts

For SaaS businesses, service shops and production businesses.
```

### 3.5 Play Store Review

- First app: 7-10 business day review
- Updates: 1-3 days (sometimes hours)
- Publish to `Internal testing` first to speed things up

## 4. iOS — App Store

### 4.1 Configure signing (EAS manages it)

```bash
# EAS can automatically manage:
# - Certificates (iOS Distribution)
# - Provisioning Profiles
# - App IDs in Apple Developer Portal

# Configure credentials
eas credentials --platform ios

# Select: "Manage all" so EAS handles everything
```

### 4.2 First IPA Build

```bash
# Production build
eas build --profile production --platform ios

# The build takes ~15-25 minutes
# When done: download URL for the .ipa file
```

### 4.3 Upload to TestFlight (required before App Store)

```bash
# Submit to App Store Connect / TestFlight
eas submit --profile production --platform ios --latest

# Or manually with Transporter app (macOS):
# 1. Download .ipa from expo.dev
# 2. Open in Transporter
# 3. Deliver
```

### 4.4 Configure TestFlight

In App Store Connect:
1. Your app → `TestFlight`
2. Wait for processing (~15 min)
3. Add `What to Test`:
   ```
   Please test:
   1. Login with your account
   2. View orders list
   3. Create a quote
   4. Change an order status
   5. Share quote via messaging
   ```
4. Add internal testers (your team)
5. For external testers: complete compliance questions and submit for Apple review (~1 day)

### 4.5 Configure App Store listing

In App Store Connect → App Store → Prepare for submission:

| Field | Content |
|-------|-----------|
| Name | SaaS Template |
| Subtitle | Business CRM |
| Description | (same as Play Store, adapted) |
| Keywords | business, orders, quotes, production, crm, products |
| Screenshots | iPhone 6.7" + 6.5" + iPad (if supported) |
| App Preview | 15-30s video showing the app |
| Category | Business |
| Age rating | 4+ |
| Support URL | https://your-domain.com/support |
| Privacy policy URL | https://your-domain.com/privacy |
| Pricing | Free |
| Availability | All countries (or specific countries) |

### 4.6 Review information (App Review)

In App Store Connect → App Information → App Review Information:

```
Demo Account:
  Email: reviewer@your-domain.com
  Password: ReviewDemo2026!

Notes for Reviewer:
  This is a B2B SaaS app for business management.
  The app requires an account to access.
  Demo account has sample data with orders, customers and quotes.

  Main features to review:
  1. Login screen
  2. Dashboard with stats
  3. Orders list and detail
  4. Quote calculator
  5. Customer list
```

> **IMPORTANT:** Always provide a working demo account. Apple rejects apps without review access.

### 4.7 App Store Review

- First app: 24-48 hours (sometimes longer)
- Updates: 24-48 hours
- If rejected: read the reason, fix and re-submit

## 6. Post-Launch

### Monitoring

```bash
# View crashes and errors with Sentry
# Configure in app:
# npx expo install @sentry/react-native
# Configure in app.json and App component

# Usage metrics
# expo.dev → Projects → your project → Insights
```

### Update Process

```
Urgent bug fix (hotfix):
  1. Fix in branch hotfix/name
  2. OTA update if JS-only: eas update --branch production
  3. Full build if native required: eas build + eas submit

New feature:
  1. Develop in feature/name
  2. PR → develop → staging build
  3. QA on TestFlight/Internal Testing
  4. PR → main → production build + submit
  5. Wait for store review (~24-48h iOS, ~1-3h Android)
```

### Increment Version

```bash
# Before each release
npm version patch   # bug fix
npm version minor   # new feature
npm version major   # breaking change

# Commit the version change
git add package.json
git commit -m "chore: bump version to $(node -p "require('./package.json').version")"
```
